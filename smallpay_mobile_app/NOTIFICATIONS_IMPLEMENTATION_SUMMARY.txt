================================================================================
                          TYPES DE NOTIFICATIONS
================================================================================

Notifications qui peuvent être activées/désactivées:

1. PAIEMENTS
   - Paiements réussis
   - Paiements échoués
   - Remboursements
   - Paiements en attente

2. KYC
   - KYC approuvé
   - KYC rejeté
   - Documents manquants
   - Demandes d'informations

3. COMMANDES
   - Commandes créées
   - Changements de statut
   - Expédition
   - Livraison

4. RAPPELS
   - Paiements à venir
   - Limites d'emprunt
   - Mises à jour de compte

Chaque type peut être ACTIVÉ/DÉSACTIVÉ indépendamment

================================================================================
                        FLUX DE RÉCEPTION
================================================================================

PREMIER LANCEMENT:
──────────────────
1. App démarre
2. useNotificationsPush.initializeNotifications() appelé
3. Permission demandée: "Autoriser les notifications?"
4. Utilisateur accepte ou refuse
5. Si accepté:
   - Channels Android créés
   - Push token généré par Expo
   - Token envoyé au backend
   - Sauvegardé dans la BDD
6. App maintenant prête à recevoir notifications

RÉCEPTION NOTIFICATION (APP OUVERTE):
──────────────────────────────────────
1. Backend décide d'envoyer notification
2. Récupère le push token de l'utilisateur
3. Envoie à Expo Push Service
4. Expo envoie au FCM (Android) ou APNs (iOS)
5. App reçoit la notification en foreground
6. Listener addNotificationReceivedListener se déclenche
7. Notification affichée dans l'app (toast/banner)

RÉCEPTION NOTIFICATION (APP FERMÉE):
───────────────────────────────────
1. Backend décide d'envoyer notification
2. Récupère le push token de l'utilisateur
3. Envoie à Expo Push Service
4. Expo envoie au FCM (Android) ou APNs (iOS)
5. Système d'exploitation affiche la notification
6. Utilisateur voit une notification dans le system tray
7. Utilisateur appuie sur la notification
8. App se lance
9. Listener addNotificationResponseReceivedListener se déclenche
10. Redirection vers l'écran pertinent (paiements, profil, etc.)

================================================================================
                          DÉPANNAGE RAPIDE
================================================================================

PROBLÈME: Token est null
────────────────────────
Cause: EXPO_PROJECT_ID manquant
Solution:
1. Vérifier .env.local contient: EXPO_PROJECT_ID=...
2. Aller sur https://expo.dev/projects
3. Copier l'ID du projet
4. Redémarrer l'app

PROBLÈME: Pas de permission demandée
──────────────────────────────────
Cause: Android < 13 ou iOS < 14
Solution: Test sur Android 13+ ou iOS 14+

PROBLÈME: Notification ne s'affiche pas
────────────────────────────────────────
Cause: Permissions refusées
Solution:
1. Accès aux paramètres du téléphone
2. SmallPay > Permissions > Notifications
3. Accorder la permission
4. Relancer l'app

PROBLÈME: App crash au démarrage
────────────────────────────────
Cause: Erreur d'import ou de syntaxe
Solution:
1. Vérifier les imports de useNotificationsPush
2. Vérifier expo-notifications installé
3. Vérifier expo-device installé
4. Consulter les logs: npm run ios/android

PROBLÈME: Backend ne reçoit pas le token
─────────────────────────────────────────
Cause: Endpoint manquant ou URL incorrect
Solution:
1. Vérifier POST /notifications/push-token existe
2. Vérifier l'URL dans PushNotificationService
3. Tester l'endpoint avec Postman
4. Vérifier les logs Laravel
