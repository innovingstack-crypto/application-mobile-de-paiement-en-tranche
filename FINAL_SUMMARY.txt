================================================================================
                            ARCHITECTURES
================================================================================

FLUX UTILISATEUR:
────────────────
User → Signup → Products → Order → KYC Submission → Admin Approve
                                         ↓
                           ✨ NOUVEAU SYSTÈME ✨
                                         ↓
      Verify KYC → Payment Review → Campay Processing → Success Screen
                                         ↓
                          6 Monthly Payments Scheduled

ENDPOINTS API CRÉÉS:
────────────────────
POST   /api/payments/deposit              → Initiate deposit payment (30%)
POST   /api/payments/monthly              → Initiate monthly payment
GET    /api/payments/{reference}/status   → Check payment status
GET    /api/orders/{orderId}/payments     → Payment history
GET    /api/orders/{orderId}/schedule     → Payment schedule

MODELS CRÉÉS/AMÉLIORÉS:
───────────────────────
Order:
  + payment_status (pending, partial, completed)
  + payment_method (campay, card, etc.)
  + deposit_reference (Campay reference)
  + deposit_paid_at (timestamp)
  + is_kyc_required (boolean)
  + kyc_verified_at (timestamp)
  + verified_by (FK to user)

CampayPayment:
  + user_id (FK)
  + order_id (FK)
  + payment_schedule_id (FK)
  + payment_type (deposit, installment)

Services:
  PaymentFlowService: Logique complète du flux de paiement
  CampayService: Intégration Campay améliorée

================================================================================
                         POINTS CLÉS
================================================================================

1. KYC OBLIGATOIRE
   └─ Pas de paiement sans KYC approuvé

2. ACOMPTE FIXE 30%
   └─ Collecté immédiatement après KYC

3. PLANNING AUTO
   └─ 6 échéances créées après dépôt réussi

4. CAMPAY INTEGRATION
   └─ Mobile money (MTN, Orange, etc.)

5. WEBHOOK CRUCIAL
   └─ Finalise le paiement et le planning

6. POLLING FALLBACK
   └─ Si webhook échoue, client peut vérifier

7. LOGGING EXTENSIF
   └─ Tous les paiements loggés

8. SÉCURITÉ
   └─ KYC, rate limiting, audit trail
